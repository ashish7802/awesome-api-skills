## 📖 Why This Exists

### The Problem: AI Agents Hallucinate APIs

When you ask Claude, Cursor, or GitHub Copilot to "add Stripe payments to my app," here's what usually happens:

| ❌ Without Structured Skills | ✅ With Awesome API Skills |
|:---|:---|
| **Invents webhook event names** that don't exist (`payment.success` instead of `payment_intent.succeeded`) | **Exact event names** from verified `SKILL.md` — `payment_intent.succeeded`, `invoice.payment_failed` |
| **Uses deprecated SDK methods** from old blog posts or training data | **Current SDK patterns** with version-aware examples |
| **Mixes test and live API keys** in the same file | **Environment isolation** clearly documented in the authentication section |
| **Skips webhook signature verification** — "just parse the JSON body" | **Security-first** — raw body buffer + `stripe.webhooks.constructEvent()` |
| **Recommends wrong architecture** — storing raw card numbers | **PCI compliance** guidance built into every payment skill |
| **Pastes 10 pages of docs** into chat every new session | **One skill folder** in your repo context — the agent reads it automatically |

> **Real example:** An agent once suggested `stripe.charges.create()` for a new checkout flow. The correct modern pattern is `stripe.checkout.sessions.create()` — but the agent learned from old StackOverflow posts. Our Stripe skill prevents this.

### What This Is (And Isn't)

| This Is | This Isn't |
|:---|:---|
| **Structured instruction packs** for AI coding agents | ❌ A tutorial or course for humans |
| **Production checklists** — what to verify before shipping | ❌ API reference documentation (we link to official docs) |
| **AI-specific pitfalls** — what Claude/Cursor/Copilot get wrong | ❌ Generated by AI — every skill is human-curated |
| **A knowledge graph** showing which APIs work together | ❌ A random list of links |
| **Copy-pasteable into your project** (`.cursor/skills/`, `.claude/`) | ❌ A SaaS you need to sign up for |

## 🚀 Quick Start

### Option A: Drop a Skill Into Your Project (30 Seconds)

The fastest way. No installation. No dependencies.

```bash
# 1. Clone or download just the skill you need
git clone --depth 1 https://github.com/ashish7802/awesome-api-skills.git

# 2. Copy the skill to your agent's context directory
# For Cursor:
cp -r awesome-api-skills/skills/stripe .cursor/skills/

# For Claude Code:
cp -r awesome-api-skills/skills/stripe .claude/skills/

# 3. Tell your agent:
# "Follow .cursor/skills/stripe/SKILL.md when working with payments"
```

> **💡 Pro tip:** Add `.cursor/skills/` to your repo. Now every teammate's agent uses the same verified patterns.

### Option B: Browse All Skills Locally

```bash
# 1. Clone the repository
git clone https://github.com/ashish7802/awesome-api-skills.git
cd awesome-api-skills

# 2. Install dependencies (pnpm required)
pnpm install

# 3. Build all packages
pnpm build

# 4. Start the local docs site
pnpm dev
# → Open http://localhost:5173/skills/
```

### Option C: Search via CLI (Build from Source)

```bash
# After pnpm build:
node packages/cli/dist/bin.js search "payment"
# → Shows: stripe, paddle, lemon-squeezy, plaid, revenuecat

node packages/cli/dist/bin.js doctor
# → Validates all 100 skills against the schema

node packages/cli/dist/bin.js graph --skill stripe
# → Shows related skills: express, postgresql, webhooks
```

> **⚠️ Note:** The CLI is not yet published to npm. We're actively working on it — [track progress](https://github.com/ashish7802/awesome-api-skills/issues) or [help us ship it](CONTRIBUTING.md).

## 🏗️ How It Works

### The Skill Format: A Standardized Contract

Every skill follows the exact same structure. This means your agent always knows where to look for what:

```
skills/<api-name>/
├── SKILL.md              ← 📘 The main instruction file (AI-optimized)
├── metadata.json         ← 🤖 Machine-readable schema, tags, version
├── examples/
│   ├── basic-checkout.js
│   ├── webhook-handler.ts
│   └── error-handling.py
├── prompts/
│   └── system-prompt.md  ← Pre-optimized prompt for this API
└── tests/
    └── validation.test.ts ← Automated checks that this skill is valid
```

### What's Inside SKILL.md?

This isn't documentation. It's **agent instructions**. Every SKILL.md has 7 mandatory sections:

| Section | What It Covers | Why Agents Need It |
|:---|:---|:---|
| **1. Overview** | What this API does, when to use it | Prevents agents from using Stripe when PayPal is requested |
| **2. Installation** | Exact package names and versions | Prevents `npm install stripe` vs `npm install @stripe/stripe-js` confusion |
| **3. Authentication** | How to connect, key types, security rules | Prevents hardcoding secrets, mixing test/live keys |
| **4. Core Concepts** | The 3–5 abstractions you must understand | Prevents agents from using low-level APIs when high-level ones exist |
| **5. Common Workflows** | Step-by-step patterns for typical tasks | "Create checkout → handle webhook → fulfill order" |
| **6. Error Handling** | Status codes, error types, retry logic | Prevents silent failures and infinite retry loops |
| **7. AI Pitfalls** ⭐ | **What agents specifically get wrong** | Unique to this project — see the example below |

### Example: AI Pitfalls Section (from the Stripe skill)

```markdown
## AI Pitfalls

- ❌ **Inventing webhook events** — Agents often guess `payment.success`.
  ✅ Correct: `payment_intent.succeeded`, `invoice.payment_failed`

- ❌ **Using parsed JSON body for webhooks** — `req.body` breaks signature verification.
  ✅ Correct: Use `express.raw({type: 'application/json'})` + `stripe.webhooks.constructEvent(payload, sig, secret)`

- ❌ **Storing raw card numbers** — Violates PCI compliance.
  ✅ Correct: Use Stripe Elements or Checkout Sessions. Never touch raw card data.

- ❌ **Forgetting idempotency keys** — Duplicate charges on retry.
  ✅ Correct: Add an `Idempotency-Key` header to all POST requests.
```

This section is **why this project exists**. It's the difference between an agent that sounds confident and an agent that ships secure, correct code.

## 🔗 Knowledge Graph

Skills don't exist in isolation. APIs connect to each other:

```
Building a SaaS? Your agent should know:

stripe ──requires──→ express/fastapi/nestjs
   │                    │
   └──requires──→ postgresql ──requires──→ prisma/drizzle
   │                    │                    │
   └──requires──→ clerk/auth0 ──requires──→ jwt/oauth2
   │
   └──monitored by──→ sentry/datadog
   │
   └──deployed on──→ vercel/railway/fly
```

The `registry/graph.json` file encodes these relationships. When your agent reads the Stripe skill, it also sees:
- **Prerequisites**: You need a backend framework and a database first
- **Alternatives**: Paddle or Lemon Squeezy for different use cases
- **Complements**: Sentry for error tracking, Clerk for auth

This prevents agents from trying to add Stripe before setting up a backend, or choosing the wrong database for a payment-heavy workload.

### What We Guarantee

Every skill in this repository meets these minimum standards:

- ✅ Valid `metadata.json` schema (enforced by `pnpm test`)
- ✅ `SKILL.md` with all 7 required sections
- ✅ AI Pitfalls section (our unique value)
- ✅ No "official" claims unless verified by the vendor

## 🤝 Contribute

This project needs you to reach its potential. Here's exactly how to help.

### 🎯 Upgrade a Skill to ⭐ Verified

Pick any 🚧 Draft or 📝 Community skill and improve it:

1. **Add real, runnable code examples** in `examples/` (not pseudo-code)
2. **Expand the AI Pitfalls section** — what specifically does Claude/Cursor get wrong?
3. **Add a Production Checklist** with `[ ]` checkboxes:
   ```markdown
   ## Production Checklist
   - [ ] Webhook signatures verified on raw body
   - [ ] Idempotency keys on all mutating requests
   - [ ] Test and live keys isolated by environment
   - [ ] Rate limiting and retry logic configured
   - [ ] Error handling covers all documented error types
   ```
4. **Update `metadata.json`**:
   ```json
   {
     "quality": "verified",
     "lastVerified": "2026-06-29",
     "verifiedBy": "your-github-username"
   }
   ```
5. **Open a PR** with `[verified]` in the title

### ➕ Add a New Skill

```bash
# 1. Use the generator
node scripts/generators/build-skill-v4.js

# 2. Follow the template in SPECIFICATION.md
# 3. Write all 7 SKILL.md sections
# 4. Add at least 2 code examples
# 5. Run validation
node scripts/dev/run-validation-v2.js

# 6. Open a PR with [new-skill] in the title
```
